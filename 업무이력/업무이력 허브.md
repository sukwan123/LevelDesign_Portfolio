### 목업이 작게 나오는 문제 해결 — 행 단위 분할 (2026-09-15)
9장을 한 파일로 합치면 슬라이드에서 각 이미지가 1/9 크기라 안 보인다.
**3장씩 가로 1행으로 쪼개서** 한 파일 = 한 행 = 슬라이드 한 줄이 되게 했다.
파일명에 `_1of3` 표기 → 젠스파크가 "슬라이드 폭 가득, 행 1개당 슬라이드 1장"으로 배치.

**행 합성은 가변 폭 패킹**: 셀을 멤버 최대 크기로 잡으면 좌우에 흰 여백이 크게 남는다.
각 이미지를 원본 폭 그대로 나란히 이어붙이고 세로만 가운데 정렬 → 여백 최소, 확대·축소 0.

현재 세트: **50개 / 91MB** (한계 80개, 30개 여유)
슬롯 구성 = 평면도 9 · 목업 18 · 실작업 23 (전부 3장/행) · 기능 1
스크립트: 스크래치패드 `build_upload2.py` (행 분할), 스펙 md는 v12 HTML에서 자동 생성

### 젠스파크 업로드 한계 80개 대응 (2026-09-15)
젠스파크 첨부 한계가 **80개**라 v12의 119장을 그대로 못 올린다.
**`젠스파크_업로드\` 폴더에 79개 세트를 별도로 만들어 둠** (83MB). v12/images 는 마스터로 보존.

**무엇을 합쳤는가 — 손실 최소 기준**
- **평면도 9개: 개별 유지** (가장 중요, 글자·치수 있음)
- **목업: 섹션별 1장으로 격자 합성** (보조 자료, 어차피 격자로 보여줌)
  최북단·올드타운·하이가든·크로우즈네스트 각 9장→1, 하렌홀 6장→1. 그리핀·크라켄·맘모스는 원래 1장
- **실작업 캡처: 개별 유지** (PPT에서 크게 다룰 주력 이미지) — 단 장벽너머 3장만 합성
- 기능 카드 2장 → 1장 합성
합계 9 + 8 + 60 + 1 + 1 = **79개**

**합성 방식 — 확대·축소 금지**
셀 크기 = 멤버 중 최대 크기. 작은 이미지는 확대하지 않고 가운데 배치.
→ 각 멤버의 원본 픽셀 크기가 그대로 남는다. 검증: 합성본에서 멤버 영역을 떼어
원본과 PSNR 비교 → 39~48dB, 크기 전부 동일.
**합성은 반드시 `assets\` PNG 마스터에서 할 것.** v12 JPEG에서 합성하면 이중 압축된다.

파일명에 `N장합성`을 넣어 젠스파크가 "쪼개지 말고 한 장으로 배치"하도록 스펙에 명시했다.
스크립트: 스크래치패드 `build_upload.py`

**v11 방식**
- HTML은 이미지를 **상대경로로 참조**한다. base64 0건, HTML 자체는 45KB.

**HDR 디코딩 방법** — PIL로는 안 열린다. Radiance RGBE 무압축이라 직접 디코딩:
헤더에서 `
-Y <h> +X <w>` 줄을 찾아 그 다음 바이트부터 h*w*4 uint8 → RGBE.
값 = mantissa * 2^(E-136) (256 나눗셈 포함), 99.5 퍼센타일로 정규화 후 감마 1/2.2.
크라켄은 타일 2장(`minimap0_0.hdr`, `minimap1_0.hdr`)이라 좌우로 이어야 한다.

### 젠스파크 실측 (2026-09-16 PDF 39장 결과 분석)
- **젠스파크는 업로드 이미지를 긴 변 1024px로 강제 리샘플한다.** PDF 내 이미지 78개 중 75개가 정확히 1024.
  2560x1392 캡처가 1024x557로 들어갔다. → 원본 해상도로 올리는 건 업로드 시간 낭비일 뿐 의미 없음.
- **미리 합성한 몽타주는 이중 손해.** 9장을 한 장에 합치면 그 1024px 예산을 9등분 → 셀당 약 340px.
  개별로 주면 각 장이 1024px을 받는다. "몽타주가 작게 나온다"의 진짜 원인이 이것.
- **젠스파크의 자체 격자 배치는 훌륭하다.** PDF p07/p25(개별 6장)는 여백 없이 꽉 찬 3열.
  반면 p06/p10/p14/p18(내 9장합성)은 흰 여백 범벅. → 합성하지 말고 개별로 주는 게 맞다.
- 업로드 세트는 **긴 변 1024 Lanczos**로 내가 한 번만 리샘플: 81MB → 23MB (동일 결과, 업로드만 빨라짐).
- 원본 해상도는 젠스파크 안에서는 달성 불가 → **PPTX를 받은 뒤 되돌린다.**
  `포트폴리오 for Claude/도구/relink_pptx.py` : ppt/media 를 썸네일 서명으로 원본과 대조해 바이트 교체.
  검증: PDF 추출 이미지 78개 중 개별 이미지 71개 전부 정확 매칭, 실패 7개는 전부 내가 합성한 몽타주.
  (= 합성본은 원본 복구조차 불가능하다는 또 하나의 근거)
